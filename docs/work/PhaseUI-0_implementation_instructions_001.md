FeatherScribeのUI刷新ロードマップに基づき、Phase UI-0「ビジュアル方針の固定」を実施してください。

# 目的

FeatherScribeのWPF UIを高品質にブラッシュアップする前段として、デザインの方向性、レイアウト、色、余白、角丸、タイポグラフィ、アニメーション原則を文書化し、今後のUI実装におけるSSOTを作成します。

今回はビジュアル仕様の確定が目的です。

本番UIのXAML、C#コード、音声入力、文字起こし、LLM整形、ホットキー、クリップボード処理などの既存動作は変更しないでください。

# プロジェクト前提

FeatherScribeは、Windows上で動作する個人利用向けWPF音声入力アプリです。

主要な処理フロー:

1. ホットキーで録音開始
2. whisper.cppで文字起こし
3. 必要に応じてローカルLLMで整形
4. クリップボードへの格納または入力先への貼り付け

本アプリは製品配布を前提としません。

以下は今後も原則として追加しません。

* モデル選択画面
* 複雑な設定画面
* テーマ切り替え
* プラグイン機構
* ユーザーアカウント
* クラウド連携
* 自動更新
* 複数ユーザー対応
* 高度なプロファイル管理画面

ダークテーマ固定で構いません。

# デザインコンセプト

FeatherScribeという名称に合わせ、次の印象を目指してください。

* 軽やか
* 静か
* 知的
* 高品質
* 現代的
* 過度に派手ではない
* 音声入力の処理状態が直感的に分かる
* 長時間使用しても疲れにくい

羽根、インク、筆記、淡い光、静かな動きのイメージを取り入れて構いません。

ただし、羽根のイラストを大量に使ったり、装飾的な世界観を強く押し出したりしないでください。

「業務ツールとして使える落ち着き」と「個人用ツールとしての上質さ」の両立を目指してください。

## 3. カラーパレットを定義する

ダークテーマ固定のカラーパレットを定義してください。

カラー値はHEXで具体的に決めてください。

最低限、次の用途を定義してください。

```text
WindowBackground
Surface
SurfaceElevated
SurfaceHover
Border
BorderStrong
PrimaryText
SecondaryText
MutedText
Accent
AccentHover
AccentPressed
Recording
Success
Warning
Danger
OverlayBackground
Selection
Focus
```

方向性の参考:

* 背景は黒ではなく、濃いチャコールまたは濃紺
* Surfaceは背景と明確に区別できるが、明るすぎない
* 主文字は純白ではなくオフホワイト
* アクセントは淡いシアン、青緑、またはブルーグリーン
* 録音中は落ち着いた赤
* 警告はアンバー
* 成功は緑
* 境界線は低コントラスト
* フォーカスはアクセントカラーで明確にする

色数を増やしすぎないでください。

各色について、用途と使用禁止例も簡潔に記載してください。

例:

```text
Recording:
録音中のインジケーターとパルスにのみ使用する。
通常の強調ボタンには使用しない。
```

## 7. 境界線と影を定義する

影だけで領域を区切らず、薄い境界線と組み合わせてください。

次の用途を定義してください。

```text
StandardBorder
ElevatedBorder
SubtleShadow
OverlayShadow
FocusRing
```

WPFで過度に重いDropShadowEffectを大量使用しない方針を明記してください。

影は主要カード、オーバーレイ、トーストなど、必要な箇所だけに限定してください。

## 8. MainWindowのワイヤーフレームを作成する

`docs/ui/visual_direction.md` 内にASCIIワイヤーフレームを記載してください。

推奨構成:

```text
┌────────────────────────────────────────────┐
│ FeatherScribe                    ● 待機中  │
│ ローカル音声入力                            │
├────────────────────────────────────────────┤
│                                            │
│  直近の結果                                │
│  ┌──────────────────────────────────────┐  │
│  │ 今日の会議は、まず午前10時から…     │  │
│  │                                      │  │
│  └──────────────────────────────────────┘  │
│                                            │
│  [コピー] [直前の入力先へ貼り付け]         │
│                                            │
│  ▸ 整形候補・警告                          │
│                                            │
├────────────────────────────────────────────┤
│ [再整形]                       [操作ガイド] │
└────────────────────────────────────────────┘
```

このワイヤーフレームをそのまま採用する必要はありませんが、次を満たしてください。

* 直近結果が最も目立つ
* コピーと貼り付けが主要操作
* モデル名や詳細設定を常時表示しない
* 不採用候補や警告は折りたたみ可能
* ホットキー一覧がメイン領域を圧迫しない
* 画面全体が設定画面のように見えない
* 日常利用時に必要な情報だけが見える

## 9. RecordingOverlayのワイヤーフレームを作成する

```text

└──────────────────────────┘
```

```text
┌──────────────┐
│ ✓ 完了       │

```

```text
┌──────────────────────────────┐
│ △ 未整形の文章を使用しました │
└──────────────────────────────┘
```

オーバーレイについて、次の方針を明記してください。

* フォーカスを奪わない
* 操作対象アプリを妨げない
* 画面下部中央を基本位置とする
* 状態ごとに色と動きが変わる
* 完了後は自動でフェードアウトする
* エラー全文を表示しない
* 長時間表示しても邪魔にならない

## 11. モーション原則を定義する

後続Phaseで実装するアニメーションの方針を確定してください。

共通時間:

```text
Fast: 100ms
Normal: 180ms
Slow: 260ms
```

使用する動き:

* Fade
* 4pxから12px程度の短いSlide
* Scale 0.97から1.0
* 色の補間
* 折りたたみ領域の高さ変化
* 録音中の穏やかなPulse

禁止する動き:

* 大きなバウンド
* 激しい回転
* ウィンドウ全体の大きな移動
* 操作完了を遅らせる演出
* 多数の要素を連続して動かす演出
* 常時動き続ける装飾

アニメーションは装飾ではなく、状態変化と操作結果を伝えるために使用すると明記してください。
